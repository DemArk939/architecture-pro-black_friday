## Задание 7. Проектирование схем коллекций для шардирования данных

«Мобильный мир» хранит информацию о заказах, товарах и корзинах в трёх коллекциях в MongoDB.

### Коллекция orders включает заказы клиентов и содержит атрибуты:

1. Уникальный идентификатор заказа;
2. Идентификатор клиента;
3. Дату и время оформления заказа;
4. Список заказанных товаров и их цену;
5. Статус заказа;
6. Общую сумму заказа;
7. Геозону заказа.

Например, заказ пользователя из Москвы может включать товары из категорий «Электроника» и «Книги».

Основные операции:

- Быстрое создание заказов с одновременным списанием остатков.
- Поиск истории заказов конкретного пользователя.
- Отображение статуса заказа.

```json
{
  "_id": "64c9f3a7d4b34716873b9f2e",
  "customer_id": 12345,
  "order_date": "2023-08-10T14:30:00Z",
  "items": [
    {
      "product_id": 1001,
      "price": "1999.99",
      "quantity": 2
    },
    {
      "product_id": 1002,
      "price": "59.99",
      "quantity": 1
    }
  ],
  "status": "processing",
  "total_amount": "4059.97",
  "geo_zone": "Москва"
}
```

Для улучшения производительности определённых операций рекомендуем создать необходимые индексы:

- **Индекс по customer_id**

Создать индекс по полю customer_id, чтобы быстро находить историю заказов конкретного пользователя:

```javascript
db.orders.createIndex({"customer_id": 1})
```

Это ускорит выполнение поисковых запросов вида:

```javascript
db.orders.find({"customer_id": userID})
```

- **Индекс по status**

Создать композитный индекс по полям status и order_date. Это полезно для отображения текущих заказов пользователей и
мониторинга активности:

```javascript
db.orders.createIndex({"status": 1, "order_date": -1})
```

Такой индекс оптимизирует запросы типа:

```javascript
db.orders.find({"status": "processing"}).sort({order_date: -1});
```

- **Индексация геозоны**

Если планируется часто искать заказы по регионам, можно добавить индекс по полю geo_zone:

```javascript
db.orders.createIndex({"geo_zone": 1})
```

Что позволит эффективно выбирать заказы из конкретных регионов.

#### Шардирование

Можно использовать в качестве ключа шардирования хеш по customer_id.

Это позволит:

- более равномерно распределить данные по БД
- распределить нагрузку на сервера
- выбрать все заказы одного пользователя сразу из одной шарды, а значит максимально быстро

### Коллекция products хранит сведения о товарах и включает такие атрибуты:

1. Уникальный идентификатор товара;
2. Наименование;
3. Категорию товара;
4. Цену;
5. Остаток товара в каждой геозоне;
6. Дополнительные атрибуты (цвет, размер).

Например, в Екатеринбурге есть в наличии 50 штук товара «Смартфон X», а в Калининграде — 30.

Основные операции:

- Частые обновления остатков при покупках.
- Поиск товаров по категориям и фильтрация по диапазону цен.
- Описание товара на странице продукта.

```json
{
  "_id": "64c9f3a7d4b34716873b9f2e",
  "name": "Denon avr-4700",
  "category": "music",
  "price": "150000.00",
  "stocks": [
    {
      "geo_zone": "Москва",
      "quantity": 15
    },
    {
      "geo_zone": "Самара",
      "quantity": 5
    }
  ],
  "attributes": {
    "color": "black",
    "size": "400x350x150"
  }
}
```

Для уменьшения запаса товара можно использовать такой запрос:

```javascript
db.products.updateOne(
    {_id: "64c9f3a7d4b34716873b9f2e", "stocks.geo_zone": "Москва"},
    {$inc: {"stocks.$.amount": -2}}
)
```

Для улучшения производительности определённых операций рекомендуем создать необходимые индексы:

- **Индекс по category и price**

Создать индекс по полю category и price, чтобы быстро находить нужные товары c одновременной фильтрацией по ценам:

```javascript
db.products.createIndex({"category": 1, "price": 1})
```

Это ускорит выполнение поисковых запросов вида:

```javascript
db.orders.find({"category": "music", "price": {$gte: 1000, $lte: 5000}})
```

#### Шардирование

Так как одной из основных операций - это поиск по категории
Можно использовать в качестве ключа шардирования хеш по category продукта.

Это позволит обеспечить баланс между распределением данных и скоростью поиска нужных записей.

### Коллекция carts хранит данные о текущих корзинах (как гостевых, так и пользовательских) и включает атрибуты:

1. Уникальный идентификатор корзины (_id);
2. Идентификатор пользователя (user_id) и session_id для гостей;
3. Список товаров (items): массив документов { product_id, quantity };
4. Статус корзины (status): "active" | "ordered" | "abandoned";
5. Дату и время создания (created_at);
6. Дату и время последнего обновления (updated_at);
7. Время удаления (TTL) (expires_at) — для автоматической очистки старых корзин.

Основные операции:

- Создание корзины, когда заходит гость или новый пользователь. Получение текущей корзины по фильтру { session_id,
  status:"active" } или { user_id, status:"active" }.
- Добавление или замена товара в корзине.
- Удаление товара из корзины.
- Слияние гостевой корзины в пользовательскую, если пользователь залогинится:
    - прочитать гостевую { session_id, status:"active" };
    - добавить её items в корзину { user_id, status:"active" };
    - отметить гостевую как abandoned.
- Отметка корзины как заказанной.

```json
{
  "_id": "64c9f3a7d4b34716873b9f2e",
  "user_id": "64c9f3a7d4b34716873b9f2e",
  "session_id": "abc123",
  "items": [
    {
      "product_id": 1001,
      "price": "1999.99",
      "quantity": 2
    },
    {
      "product_id": 1002,
      "price": "59.99",
      "quantity": 1
    }
  ],
  "status": "active",
  "created_at": "2023-08-10T14:30:00Z",
  "updated_at": "2023-08-10T14:30:00Z",
  "expires_at": "2023-08-10T14:30:00Z"
}
```

Для улучшения производительности определённых операций рекомендуем создать необходимые индексы:

- **Индекс по user_id**

Создать индекс по полю user_id:

```javascript
db.products.createIndex({"user_id": 1})
```

Это ускорит выполнение поисковых запросов вида:

```javascript
db.orders.find({"user_id": "64c9f3a7d4b34716873b9f2e"})
```

- **Индекс по session_id**

Создать индекс по полю session_id:

```javascript
db.products.createIndex({"session_id": 1})
```

Это ускорит выполнение поисковых запросов вида:

```javascript
db.orders.find({"session_id": "abc123"})
```

- **TTL-индекс для удаления устаревших корзин**

```javascript
db.carts.createIndex({expires_at: 1}, {expireAfterSeconds: 0});
```

Для добавления или замены элемент в корзине можно использовать такой запрос:

```javascript
db.carts.updateOne(
    {_id: ObjectId("64c9f3a7d4b34716873b9f2e")},
    {$set: {"items.$[item].quantity": 3}},
    {arrayFilters: [{"item.product_id": 1001}], upsert: true}
);
```

Для удаления товар из корзины:

```javascript
db.carts.updateOne(
    {_id: ObjectId("64c9f3a7d4b34716873b9f2e")},
    {$pull: {items: {product_id: 1001}}}
);
```

Для слияния гостевой корзины в пользовательскую:

```javascript
// Читаем гостевую корзину
let guestCart = db.carts.findOne({session_id: "ABC123", status: "active"});

// Добавляем элементы гостевой корзины в существующую корзину пользователя
db.carts.updateOne(
    {_id: "64c9f3a7d4b34716873b9f2e"},
    {$push: {items: {$each: guestCart.items}}}
);
}
```

#### Шардирование

Можно использовать в качестве ключа шардирования комплексный ключ по user_id и session_id.

Такая конструкция позволяет системе корректно распределять данные:

- Новые пользователи (только с session_id) попадут на шард, определяемый парой (null, session_id).
- Зарегистрированные пользователи (только с user_id) попадут на шард, определяемый парой (user_id, null).

Это позволит:

- более равномерно распределить данные по БД
- распределить нагрузку на сервера
- получать информацию о пользователе и его корзине из одной шарды, что ускорит часть операций

## Задание 8. Выявление и устранение «горячих» шардов

Для мониторинга состояния шардов можно использовать следующие метрики:

- метрика дискового пространства - контроль занимаемого пространства
- метрики количества операций чтения/записи - контроль распределения операций по шардам
- метрика очереди запросов в БД - контроль способности шарды обрабатывать нужный объем запросов
- метрика баланса данных - анализ степени распределения данных по шардам
- метрика загрузки процессора - повышенная утилизация будет говорить о чрезмерной нагрузке на шард

Для того чтобы справиться с горячими шарадми, необходимо пересмотреть ключ для шардирования.

Если в качестве ключа шрадирования выбрана только Категория товара, то лучше сделать комбинированный ключ шардирования.
Например, категорию и ИД продукта.

Для это необходимо:

- Создать новую коллекцию с новым ключом шардирования:

```javascript
sh.shardCollection('myDatabase.products_new', {category: 1, _id: "hashed"})
```

- Скопируем данные из старой коллекции в новую

```javascript
db.products.find().forEach(function (doc) {
    db.products_new.insertOne(doc);
})
```

- Удалите старую коллекцию и переименуйте новую

```javascript
db.products.drop()
db.products_new.renameCollection('products')
```

- Настроим автоматическую балансировку

```javascript
db.adminCommand({balancerStart: 1})
```

- Оптимизация Chaining Process

```javascript
db.adminCommand({enableBalancerJitter: true})
```

## Задание 10. Миграция на Cassandra: модель данных, стратегии репликации и шардирования

### Задание 10.1

Самыми критически важными данными для работы Интернет магазина являются выделенные ранее данные:
- товары
- заказы
- корзины

Так как во время работы с инетрнет магазином пользователь активно ведет работу с катологом, просматривает товары,
изменяет данные в корзине, а также оформляет и изменяет заказы.

БД Casandra имеет высокие показателя производительности, но также в ней отсутствует строгая согласованности ACID.
Поэтому такие данные как корзина и заказы лучше оставить в более надежной БД.

Для переноса в БД Casandra вполне подойдет каталог Товаров. Также можно перенести историю заказов для разгрузки основной БД.

### Задание 10.2

Запросы для создания структуры в БД Casandra:
```sql
CREATE TABLE Orders (
    order_id UUID,        -- Уникальный идентификатор заказа
    customer_id INT,      -- Идентификатор клиента
    order_date TIMESTAMP, -- Дата заказа
    status TEXT,          -- Статус заказа
    total_amount DECIMAL, -- Суммарная стоимость заказа
    geo_zone TEXT,        -- Географическая зона
    PRIMARY KEY ((customer_id), order_date, order_id)
    ) WITH CLUSTERING ORDER BY (order_date DESC, order_id ASC);
```
- Partition key: customer_id. Это гарантирует, что все заказы одного клиента будут располагаться на одном узле (партиции), 
что сделает запросы по клиенту максимально эффективными.
- Clustering column: теперь состоит из двух компонент:
order_date: обеспечивает сортировку заказов по дате.
order_id: служит гарантией уникальности строки (так как два заказа с одинаковой датой и клиентом обязаны иметь уникальный идентификатор).

```sql
CREATE TABLE OrderItems (
    order_id UUID,                 -- Уникальный идентификатор заказа
    item_number SERIAL,            -- Номер строки в заказе
    product_id INT,                -- Ид товара
    price DECIMAL,                 -- Цена товара
    quantity INT,                  -- Количество товара
    PRIMARY KEY (order_id, item_number)
) WITH CLUSTERING ORDER BY (item_number ASC);
```
- Partition key: order_id. Вся информация о позициях заказа должна быть доступна внутри одной партиции, чтобы облегчить извлечение данных.
- Clustering column: item_number. Позиции заказа будут организованы по порядку следования номеров строк, что позволит эффективно извлекать и обрабатывать данные.

```sql
CREATE TABLE ProductsByCategoryAndPrice (
    category TEXT,             -- Категория товара
    price DECIMAL,             -- Цена товара
    product_id UUID,           -- Уникальный идентификатор товара
    name TEXT,                 -- Название товара
    attributes MAP<TEXT, TEXT>, -- Атрибуты товара
    PRIMARY KEY ((category, price), product_id)
```
- Partition key: Составной ключ, состоящий из category и price. Такой подход позволяет эффективно искать товары по категориям и конкретным ценам или диапазонам цен.
- Clustering column: product_id, который обеспечивает упорядочивание товаров внутри партиции и уникальность каждой записи.


```sql
CREATE TABLE ProductsStocks (
    product_id UUID,              -- Уникальный идентификатор товара
    geo_zone TEXT,                -- Географическая зона
    quantity INT,                 -- Количество товара на складе
    PRIMARY KEY (product_id, geo_zone)
) WITH CLUSTERING ORDER BY (geo_zone ASC);
```
- Partition key: product_id. Используется для партиционирования данных по товару, что позволяет равномерно распределить данные по узлам.
- Clustering column: geo_zone. Позволяет сортировать данные внутри партиции по географической зоне, что даст возможность эффективно искать информацию о запасах товара в конкретных регионах.

### Задание 10.3

История заказов:

Для сохранения целостности и согласованности данных будем использовать Hinted Handof, 
если была временная недоступность одной из нод кластера.
При длительной недоступности будем использовать механизм Anti-Entropy Repair.
Read Repair не подходит для этих данных, так как историю заказов могут просматривать не так часто, 
что может привести к большому объему несогласованных данных.

Товары:

Так как товары просматривают достаточно часто, и необходимо обеспечить отображение актуальной инфомрации, 
то можно использовать Read Repair.
При длительной недоступности также лучше использовать Anti-Entropy Repair.
